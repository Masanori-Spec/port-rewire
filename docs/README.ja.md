# PortRewire

Pure Data の抽象化パッチの入力・出力を並べ替えたときに、呼び出し元の接続番号を修正する、ローカル処理の小さなツールです。

## 使い方

1. `dist/port-rewire.html` をブラウザで開きます。サーバーもアカウントも不要です
2. 変更前・変更後の抽象化 `.pd` と、呼び出し元の `.pd` を選びます。必要な補助パッチも一緒に含めます
3. 左から数えた旧ポート番号に対し、新しい番号を1対1で選びます
4. 適用するインスタンスを確認します。入れ子のキャンバスも選択できます
5. 変更をプレビューして、移行ZIPを保存します

最初から読み込まれている動作例では、旧入力 `value / gain / bias` を `gain / bias / value` へ、旧出力 `result / echo` を `echo / result` へ変更しています。対応は入力 `[2, 0, 1]`、出力 `[1, 0]` です。

## ZIPの内容

- 元の抽象化と同じファイル名の、新しい抽象化パッチ
- 修正した呼び出し元と、変更不要の補助パッチ
- 対応・適用対象・元ファイルのSHA-256を記録する `migration.json`
- 変更前後のハッシュと接続番号を記録する `receipt.json` / `receipt.txt`

保存済みの `migration.json` は、元のソースハッシュが一致するときだけ適用できます。変更済み・移行済みの呼び出し元には二重適用できません。変更のない恒等対応は元のバイト列のままです。新しく作った対応について、過去の移行履歴を自動で推測することはできません。

## 対象と制限

同じ数の、引数のない制御用 `inlet / outlet` の並べ替えが対象です。音声ポート、入力・出力の追加や削除、型変換、clone、動的なパッチ生成、外部ライブラリや検索パスの解決には対応しません。同じX座標に複数ポートがある場合は、順番を推測せず停止します。未対応のレコードも停止します。

英数字の安全なファイル名と、有効なUTF-8のパッチを使用してください。各512 KiB、呼び出し元20ファイル、合計4 MiB、各方向64ポート、合計512インスタンス・5,000接続が上限です。コメントは参考情報として表示し、ポートの意味は自動推定しません。

入力内容は送信・自動保存・実行されません。対象の接続番号以外のバイト列を保ちますが、変更後パッチの意味や動作の同等性を保証するものではありません。元のファイルを残し、別フォルダで自身のパッチを検証してから入れ替えてください。

## 検証の範囲

独自に作った制御用の算術パッチで、公式配布のPure Dataエンジンを使ったヘッドレス検証を実施しました。旧版での期待出力、新版に未修正の呼び出し元を使った失敗条件、修正版での復元、入れ子・同一出力の接続順を確認しています。取り込んだユーザーのパッチを実行する検証ではありません。

実施済みと未実施のチェックは [VALIDATION.md](VALIDATION.md) に分けて記載しています。

座標は整数の −32768〜32767、1つのトークンはUTF-8で1,000バイト未満です。オブジェクトクラスのエスケープや変数指定、未エスケープのカンマによるコマンド連鎖、未作成オブジェクトへの接続は、解釈のずれを防ぐため拒否します。
